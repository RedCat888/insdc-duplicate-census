# Log 07 — Auditing the "67 organism-level conflicts" (2026-09-15)

## Why
The report states 4,328 identity-conflict run pairs collapsing to 278 study pairs, "of which 67
are organism-level (different species or wider)". That 67 came from an automated comparison of
the two declared taxa's ENA lineages. Before contacting anyone, every one of the 67 was inspected
by hand, and NCBI's own STAT taxonomy analysis was pulled for all 737 runs involved
(`src/stat_taxonomy.py`), to answer two questions per pair: is the archive's own analysis
consistent with content identity, and which declared label does the content actually support?

## What STAT is and why it matters here
NCBI runs STAT (Katz et al., *Genome Biology* 2021) — a MinHash k-mer taxonomic classifier — on
every SRA run, including ENA/DDBJ-submitted runs it mirrors, and serves the per-run table at
`trace.ncbi.nlm.nih.gov/Traces/sra-db-be/run_taxonomy?acc=<run>&cluster_name=public`.
It is (a) an independent content fingerprint computed by the archive itself, and (b) an
organism call computed by the archive itself. So for a run declared *Listeria* whose STAT table
says *E. coli*, the archive has held the contradiction in its own database since the analysis
date — for the JCVI *Staphylococcus* case, since 2016-08-09.

## Result 1 — STAT as a third identity channel
STAT was available for 704 of 737 runs, both sides for 384 of 401 run pairs.

| | pairs |
|---|---|
| STAT computed on the same date for both runs | 51 |
| … of which tables byte-identical | **48** |
| … tables differ | 3 (all three are file-level matches with different spot counts: Picea, wheat/potato) |
| STAT computed on different dates | 333 |
| … identical `analysed` spot count | 330 |
| … different spot count | 3 (Apis, Synodontis, Actinidia — near-identical counts, file-level) |

STAT tables are only reproducible within a reference-database version: pairs analysed in 2016
and 2018 differ by ~0.1% in `identified` with identical `analysed`. So the usable channel is
"identical spot count, and identical table when the reference date matches". Under that rule
STAT contradicts content identity in **0** run-level pairs and confirms it wherever it can.

### The biggest correction
**193 of the 398 run pairs — 7 study pairs — are *Mycobacterium tuberculosis* vs
"*Mycobacterium tuberculosis complex sp.*"**: Basel, Borstel and ITM label the same isolates at
different taxonomic depth. That is a refinement the automated classifier missed because
"MTBC sp." is an unranked *sibling* leaf, not an ancestor. The nine-study *M. tuberculosis*
component remains a real **duplication** event (same file under three BioSamples at three
institutions, and the transmission-inference consequence stands) but it is **not an identity
conflict**, and the report's framing that leaned on it as one is withdrawn.

Also withdrawn: *Sterkiella histriomuscorum* vs *Oxytricha trifallax* is a taxonomic synonym
(the report lists it as a "confirmed organism conflict"); *Saccharum officinarum* vs its hybrid
cultivar and *Bambusa* vs its hybrid are refinements.

### Cases the report over-read
- **Case 3 (NIST, *E. coli* vs *Listeria*, "different phyla").** STAT: *Listeria* 19% + *E. coli*
  10%, original file `CCQMMicroDefault20130121.sff` (CCQM = the BIPM metrology working group).
  This is a deliberately mixed reference run deposited under each constituent organism, not a
  misattachment. Reclassified MIXTURE. The labels are still each incomplete, but the mechanism
  is different and less alarming.
- **Case 2 (JCVI three genera).** STAT: *Finegoldia* 30% + *S. mitis* 16% (+ *Peptoniphilus*).
  A pooled 454 run filed under each of three BioProjects. MIXTURE. This *is* an archive-quality
  problem — three "genomes" whose raw data is one pool — but again not a misattachment.
- **Case 4 (wheat/potato).** STAT of the wheat run: *Solanum tuberosum* 46% + *Aegilops tauschii*
  35%. The potato SFF is genuinely inside the wheat run. FILE_MIX; stands as stated.

### Where STAT cannot help (MISATTR_UNADJ, 19 pairs)
Plants, fish, fungi and amplicon data: STAT's reference set resolves neither side (cotton,
kiwifruit, *Picea*, catfish, orchids). The identity conflict is real; which side is wrong is not
determinable from public data. The largest such cluster is 5 study pairs / 54 small runs from
one submitter group (Seoul National University / Institute for Basic Science genome-editing
BioProjects, 2018) with *Homo*, *Mus*, *Arabidopsis* and *Brassica* labels on overlapping files;
STAT content is Chordata or Solanaceae. No inference about cause is made.

## Result 3 — the 4,328 "identity-conflict pairs" need the same tiering
Of the 4,328: 2,664 are metagenome-type label conflicts (e.g. "activated sludge metagenome" vs
"wastewater metagenome"), 1,266 metagenome-vs-organism, and 398 organism-level, of which 97
survive this audit. The paper must report these as tiers, not one number.

## Name-matching caveat in the STAT scoring
STAT tables from 2016–2018 use the taxonomy of their date (*Firmicutes*, *Lactobacillus
salivarius*, *Ruminiclostridium thermocellum*); ENA's lineage today says *Bacillota*,
*Ligilactobacillus*, *Acetivibrio*. Strict species matching therefore scores zero on renamed taxa.
Those cases (2) were resolved by hand and are marked in the curation notes.

## Bottom line for the paper
"67 organism-level conflicts" becomes "40 study pairs with genuinely incompatible declared
identities, in 15 of which the archive's own taxonomy analysis identifies the incorrect record,
and 5 of which are pooled runs deposited once per constituent". Smaller, and much harder to
argue with.

## Addendum — Case 5 (the "one library, two donors") is eight libraries, four donors
Composition-keyed comparison of all 62 runs in SRP014893 (GSE40174, Yu et al. *Nature* 2012)
and SRP015945 (GSE41245, Yu et al. *Science* 2013), fetched via batched efetch on 2026-09-15:

| GSE40174 (Nature 2012) | GSE41245 (Science 2013) | content |
|---|---|---|
| healthy donor 1, EpCAM chip (GSM987819) | healthy donor **8**, EpCAM chip (GSM1012159) | identical |
| healthy donor 1, IgG chip (GSM987820) | healthy donor **8**, IgG chip (GSM1012160) | identical |
| healthy donor 2, EpCAM (GSM987821) | healthy donor **7**, EpCAM (GSM1012157) | identical |
| healthy donor 2, IgG (GSM987822) | healthy donor **7**, IgG (GSM1012158) | identical |
| healthy donor 3, EpCAM (GSM987823) | healthy donor **5**, EpCAM (GSM1012153) | identical |
| healthy donor 3, IgG (GSM987824) | healthy donor **5**, IgG (GSM1012154) | identical |
| healthy donor 4, EpCAM (GSM987825) | healthy donor **4**, EpCAM (GSM1012151) | identical |
| healthy donor 4, IgG (GSM987826) | healthy donor **4**, IgG (GSM1012152) | identical |

Same submitter (MGH), same platform (Helicos DGE), same processing, six weeks apart. The
*Science* paper's text describes a background panel of "10 healthy donors"; four of those ten
are the *Nature* paper's four, each re-registered as a new BioSample with a study-local donor
number. **Interpretation: reuse of healthy-donor controls across two studies, deposited as new
samples rather than by reference to the existing GSMs.** That is a deposition error with a
real consequence (anyone pooling both series double-counts four donors), not evidence of
anything else, and it is how the paper and any correspondence should state it. Whether the
supplementary material of the 2013 paper discloses the reuse was not checked (not accessible
here) and must be, before the case is described in print.

The report's case 5 narrative ("we cannot tell … whether this is an annotation error or
undisclosed reuse") is superseded: the systematic 1→8, 2→7, 3→5, 4→4 mapping across both chip
types is not consistent with a single annotation slip.
